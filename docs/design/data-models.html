Commons models fwd uses

An intention requires the Commons' Intention and Creation. Add Attribution when recording someone else's intention, LastEdit after rewording and Closure after fulfillment or withdrawal. Store these components on one entity with fwd's Placement for project membership. Read Commons views directly (D213). Commons identity.principal is used only as the type of these components' references to people and agents; these hold fwd principal IDs until principals migrate.

CodeAnchor

crates/fwd-core/src/model.rs:478

An interior sub-entity of a file: a line range of one version of the file (its basis) with an identity of its own, or with no line range, the whole file at that version (Daniel, 2026-09-28, "A whole-file reference is an anchor with no line range"). The version is named by git's object id of the content the person was looking at, whether or not it was ever committed, so the same span of the same content is the same anchor on every machine. Nothing here changes after creation, except that an anchor made before these fields existed gains its key and basis once a checkout can supply them. Where the span is now in another version is computed on demand and cached outside the graph (sidecar). See docs/design/anchoring.md.

Message

crates/fwd-core/src/model.rs:615

A comment or note: free text, durable, visible, with a status. Some messages ask questions or make proposals; that is the writer's choice, not a type. What it is about lives in typed reference fields (task, anchor, scope, decision, reply_to, thread) so reverse queries work over the wire; context keeps the rest: on a message that asks something, either to, the id of the one principal it asks, or asks set to "project" (ops::ASKS_KEY), a question asked of no one in particular, which the triage agent of the scope asks_scope names answers (ops::ASKS_SCOPE_KEY), else the one that serves the whole project (until 2026-09-29 to could hold "supervisor", the role, which fwd admin migrate replaces with asks); the scope its author wrote it in, written_in (ops::WRITTEN_IN_KEY); and move (ops::MOVE_KEY) on the comment that records why a decision moved, or a task (a return, a reject, a cancel, a reopen or a rejustify: ops::transition), which every such move writes and routing reads so that no one hears of a repeal or a supersession twice (docs/design/agents-and-inbox.md, rules 11 and 12; docs/DECISIONS.md, D34, "Decision records live in the graph, with statuses, an area, links to what they govern, and a page listing them all"). Its author, or an agent that succeeded its author, may edit its text later (ops::edit_message), which changes nothing else about it but saying when and by whom.

Decision

crates/fwd-core/src/model.rs:871

A ruling recorded so that tasks, messages and other rulings can cite it by a stable name (D<number>), and so that when it is repealed or superseded everything resting on it can be found and re-justified. Architecture is one area among several: product, process, UX, naming and dependency rulings are cited and repealed the same way. FormerId

crates/fwd-core/src/model.rs:948

An id a record had before it was renumbered, which people may have cited for months in messages, commits and notes, kept so that what they wrote still finds the record. Moving the projects' separate stores into the daemon's one store gives every record a new id, and a later change of Ankurah's stored format may give it another, so a record can have several former ids, one entity each. Every place that takes an id (ops::resolve_id, the page's router, the reference parser) accepts a former id, whole or as a prefix, beside current ids. Only the move that renumbers records writes these.
