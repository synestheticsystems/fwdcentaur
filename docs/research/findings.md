# Research findings: synthesis

Written 2026-09-24. This is the synthesis across the six research notes in this directory (mainstream trackers, agent-native trackers, business models, agent inbox mechanics, code annotations, Manifold crossover and rendering). Each claim below points at the note that carries the evidence; the notes carry the sources and dates. Items the research agents could not verify against a primary source are marked unverified in the notes and are not relied on here.

## 1. Nobody has built the whole vision

No product combines a dependency graph, line-anchored annotations that route to an agent, and per-agent inboxes (`trackers-agent-native.md`, section 10). The closest partials are: Anchored Comments, a VS Code extension with git-blob-anchored threads and an MCP for agents but no graph (8 installs); Google Antigravity's inbox plus inline comments on agent output, no graph; Beads plus Gas Town mail, a graph plus messaging with no editor surface; Vibe Kanban and Conductor, inline diff comments sent to the agent with no graph; Paperclip and Claude Code agent teams, dependencies plus inboxes with no code anchors. The gap fwdcentaur fills is the join: an annotation on a line becomes a graph node, the graph carries "why", the scope makes a person's or agent's context visible, and the whole thing persists across vendors and sessions.

Demand signals exist (`business-models.md`, section 5): Linear's CEO declared human ticket-grooming dead while structured work state matters more; OpenAI's Symphony used a Linear board as an agent control plane; a Claude Code issue from September 2026 asks for exactly a task dependency graph with per-task owner, file-touch tracking, and history that survives compaction.

## 2. Storage: git-as-database failed; a real database with one writer is the pattern

Beads abandoned JSONL-in-git plus SQLite for Dolt after its author called the design "a crummy architecture that requires AI in order to work around all its edge cases"; the old design capped out around four concurrent agents (`trackers-agent-native.md`, section 1). What survives in-repo is append-only event logs with hash ids, or a merge-capable database with a single-writer embedded mode. Ankurah is exactly that shape: event-sourced, per-entity causal DAG, deterministic per-field merge, one durable node per workspace, local-first ephemeral clients with a local cache (`manifold-crossover.md`, and the Ankurah 0.9.3 characterization it cites).

Two Ankurah facts shape the topology: the 0.9 connectors do not replay writes made while disconnected (by design: an ephemeral node requires its durable node online, per Daniel), and durable-to-durable replication (two laptops both durable, reconciling later) is not an established capability; Manifold's architecture doc defers it to a later milestone with the path unverified. Locally the shape is settled: the daemon hosts the workspace's durable node and every client is an ephemeral node over the WebSocket connector. v1 is single-user and local-only on Ankurah's `PermissiveAgent`; the team shape is deferred until hosting is designed.

## 3. GitHub Issues: a projection, not a store

GitHub now has sub-issues (100 per parent, 8 levels), issue types, issue dependencies (blocked-by, GA August 2025, 50 per issue, advisory only), issue fields, and an agent-task API (`trackers-mainstream.md`, section 1). It still breaks as the store for a fine-grained graph, in this order: noise first (repository watchers get one notification per node; there is no label filter and no exclusion syntax), then write limits (80 content-creating requests per minute and 500 per hour per token; a 500-node, 800-edge graph is roughly 2.6 hours of wall clock to create), then expressiveness (two edge kinds, no "why", no provenance, line anchors only on PR review and commit comments, which go "Outdated" on the next push). Latency is fine.

The right use is a projection: mirror milestone-level tasks into a dedicated repository under a GitHub App identity so teammates who live in GitHub see the coarse picture without the noise. Linear is the strongest hosted alternative on noise and agent model but has a 250-issue free cap and no self-hosting. Among self-hostables, OpenProject has the richest typed edges and Vikunja the lightest API, but none has a graph UI, an agent inbox, typed "why" edges, discovered-from provenance, per-person scopes, or code anchors (`trackers-mainstream.md`, sections 2 to 6).

## 4. Agents: CLI plus hooks, not MCP, for shell-capable harnesses

Beads recommends CLI plus hooks over MCP for Claude Code, Cursor and Windsurf (1 to 2k tokens versus 10 to 50k for MCP schemas); Task Master ships reduced MCP modes for the same reason; Anthropic's own posts measure the context cost of tool definitions (`trackers-agent-native.md`, lessons; `agent-inbox-mechanics.md`, section A). An MCP wrapper is for MCP-only hosts, later. An HTTP or socket API is what UIs consume.

Universal patterns worth copying: "ready" means open with no active blockers; claims need leases with TTL, heartbeats and atomic checkout (Beads v1.3.0, Paperclip, Claude Code agent teams); "context rot" is real, so re-inject the tracker's state after compaction and at session start (Beads' `bd prime`, Gas Town's session-prime hook); silent failures are the recurring bug class (dark deferred items, dropped filters, lagging status).

## 5. Inboxes: delivery mechanics exist; the design lessons are about states and addressing

Claude Code offers three ways to reach a mid-task session (`agent-inbox-mechanics.md`, section A): cross-session messaging over a per-session Unix socket (delivered between tool calls during an active turn, with held/delivered/denied/expired receipts; wire format reverse-engineered, so version-fragile), channels (research preview, next-turn delivery, no ack), and hooks (`PostToolBatch` and `UserPromptSubmit` can inject `additionalContext` once per model call; `Stop` can return `decision: "block"` with a reason, capped at eight consecutive blocks). Codex CLI has the same hook shapes plus `turn/steer` through its app server; Cursor's cloud agents return busy while running; Gemini has hooks but no push (section B).

Lessons from Gas Town mail, Agent Mail, Paperclip, Linear agent sessions and Devin (section C): separate delivered-to-session, read-by-model and acted-on, and require an explicit ack; address by scope id with role fallback, never by ephemeral session id; thread every message to a task and a thread; label sender and trust level; cap write actions per run, dedupe, coalesce bursts and bound loops.

## 6. Supervisors: cheap, observable, optional, or they burn down

Gas Town cost ten times a normal session, merged a PR despite failing tests, orphaned 141 processes, and its author declared it dead in August 2026 while keeping the Beads work graph (`trackers-agent-native.md`, section 2). GitHub Agentic Workflows answers with "safe outputs": hard caps per run (one comment, three labels, one issue), dedupe by title, and auto-filed failure issues (`agent-inbox-mechanics.md`, section C). Dosu and Linear Agent show what a grooming agent does and how it is priced (cents per run, tokens at cost, gated to a paid tier; `business-models.md`, section 2). The supervisor must run as an ordinary session first (a skill plus a watch command), get a driver later, and be hosted last.

## 7. Anchoring: several handles, cheap-first resolution, never delete

Every robust system stores several independent handles for an anchor: a base identity (path plus blob or commit), a range, and content evidence (quoted lines, context, hunk or AST path); resolution runs cheap-first (same blob, then diff line mapping with move detection, then live-buffer deltas, then fuzzy quote match with a position hint) and verifies the quote after every strategy; and when the target cannot be found, nobody deletes: Gerrit widens to file level, Phabricator ghosts and links back, Hypothesis lists orphans, CodeStream offered manual reposition (`code-annotations.md`, sections 2 and 3). Manifold's pointing contract gives the vocabulary: an anchor is a sub-entity with its own identity, and location certainty, content change and availability are three separate facts (`manifold-crossover.md`).

VS Code's Comments API supports threads on any URI including both sides of a diff (the git scheme carries the ref in its query), but it never reports range shifts back to the extension, so the extension must keep its own anchor model, apply document change events itself, and recreate threads on activation (`code-annotations.md`, section 1). VS Code is building its own agent-actionable comment store for Markdown and the integrated browser, which is the closest platform primitive to an inbox and worth watching.

## 8. Graph panel: React Flow plus ELK, and Manifold's projection rules

For a webview with rich per-node interaction, @xyflow/react with elkjs layered layout in a worker (dagre fallback) is the recommendation; collapse sub-graphs and hide nodes to stay under the DOM budget; Sigma only if a fully expanded 5k-node view is ever required (`code-annotations.md`, section 4). Manifold's rules transfer as written (`manifold-rendering.md`, sections 2, 3, 5): no stored coordinates; layout must not invent relationships or imply completeness; dependency precedence is a partial order, not a chronology; duplicated appearances rather than merged entities; inspectable omissions with exact counts; Back as the primary recovery gesture, with a checkpoint before passive changes made by agents while a human is looking; and a set of acceptance tests, including "local prerequisite cycle rejection and merged-cycle visualization".

## 9. Business: governance and hosting pay; inference does not

The paid line in every comparable is hosting, identity (SSO, SAML, SCIM), governance (RBAC, audit, retention) and support; tracker seats cluster at $6 to $16, agent tooling at $20 to $60 (`business-models.md`, section 1). Every vendor that bundled inference into a flat seat repriced within a year and took the same backlash; the stable positions are tokens at cost and charging for what the vendor controls (sandbox minutes, concurrency, seats) (section 2). Hosted collaboration alone did not save Vibe Kanban at $30 per user against a free-heavy base. Standalone sync hosting is a poor business (two exits, one wind-down; reads priced at zero), so Ankurah hosting is the substrate of a workspace product, not a product (section 3). Linear set the norm that agents are free members. License recommendation: AGPL for the server with a proprietary enterprise directory, MIT or Apache for the CLI, extension and protocol, Ankurah unchanged (section 4).

## 10. Manifold: adopt the contracts, keep the implementation separate

Daniel's decision on 2026-09-24: take inspiration from Manifold but keep the implementation fully separate and pragmatic, with an eye on merging concepts or backends later. What transfers as contracts: the daemon lifecycle and startup contract, relations as entities with named roles, interior pointing that entity-ifies the selected range, the CLI grammar (capabilities, envelopes, checked writes, proposals, watch), the task model (lifecycle versus commitment, three-valued readiness, cycle rejection) and attribution rules (`manifold-crossover.md`). What does not: the renderer decision, placeness and semantic zoom machinery, knowledge item types, and the native-component substrate work, which has no landing date.

## 11. Ankurah work this implies

In rough priority: connector offline queue and replay (laptops behind NAT lose connectivity); workspace migration from a solo local durable node to a team server (event export and import); local-only collections or properties (or accept an application-level store for the working directory and session registry); a server-assigned sequence for human-readable task numbers (application-level service on the durable node); reference traversal in queries (the daemon can do two-step queries meanwhile); and later, RefSet for multi-target relations and multi-model membership for components.
