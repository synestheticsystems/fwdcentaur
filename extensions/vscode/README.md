# fwdcentaur for VS Code (proof of concept)

Three surfaces: comment threads on lines of code that become anchored comments and questions in the shared graph, started from the editor's right-click menu (the items titled `fwd: ...`) or the comment box, with every thread not resolved drawn as a highlight in files and on both sides of git diffs; the web UI's page in a panel (`fwd: Show Task Graph`, `fwd: Show Inbox Page`), whose task becomes the window's current task, so that comments and questions made in the editor go to it, with Add as a Step to make a highlight one of its steps, and where a step clicked opens the file at its lines; and an inbox view. Settings: `fwd.path` names the `fwd` binary (empty, the default: `fwd` on the PATH, else `~/.cargo/bin/fwd`); `fwd.as` acts as an agent principal. The design and what is built: `docs/design/vscode-extension.md`.

Build: first the extension host's node (`crates/fwd-host`, built with `wasm-pack build --target nodejs` into `crates/fwd-host/pkg/`), then `npm install && npm run build`, which stamps the build's version with its commit (`version.mjs`, into `dist/version.json`), copies that package's `fwd_host.js` and `fwd_host_bg.wasm` into `dist/` beside the bundle, and the web UI's built page (`crates/fwd-web/dist`, which `scripts/build-web.sh` makes, and which the build makes first when it is missing) into `dist/web/`. The inbox, the comment threads and the highlights read through the host's node with live queries; the page is a node of its own with its own connection to the daemon; starting the daemon, everything that needs git and replies still run `fwd --format json`. `npm run package` makes the VSIX with the version the build stamped (`0.0.2-<commits>.g<short hash>`, with `.dirty.<time>` for a checkout with changes not committed), which `code --list-extensions --show-versions` shows.

Test: `npm test` runs the extension in an automated VS Code (downloaded into `.vscode-test/` on the first run) against a scratch project and daemon of its own (`.vscode-test.mjs`), using `target/debug/fwd` (`cargo build -p fwd`) or `$FWD_BIN`. VS Code's IPC socket lives under `.vscode-test/`, so a checkout at a long path (a worktree under `.claude/worktrees`) runs it from a copy at a short path.
